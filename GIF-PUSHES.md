# GIF в пушах на Android

Ветка `feature/MOBILE-675-push-gif`, задача MOBILE-675. iOS: MOBILE-674.

## Что было

Стандартный загрузчик декодировал картинку через `BitmapFactory.decodeStream` и отдавал `Bitmap` в `BigPictureStyle`. От GIF оставался первый кадр.

## Почему нужен URI

- SystemUI рисует big picture в `BigPictureNotificationImageView`.
- `Icon` с `content://` URI он грузит через `LocalImageResolver` → `ImageDecoder`, и для GIF получается `AnimatedImageDrawable`.
- `Bitmap` всегда один кадр. Поэтому GIF нужно отдать файлом по URI.
- Право читать URI выдаёт NotificationManagerService. `Notification.visitUris` обходит `EXTRA_PICTURE_ICON`, и NMS выдаёт права SystemUI и слушателям уведомлений.

## Как работает теперь

- Работает только стандартный загрузчик (`MindboxImageLoader.default()`) на Android 14+ (API 34).
- Загрузчик смотрит первые 6 байт ответа. Если это GIF, поток пишется в `cacheDir/mindbox_push_images/<UUID>.gif`, а первый кадр декодируется из файла.
- `MindboxPushImageProvider` отдаёт файл. Это наследник `FileProvider` с authority `${applicationId}.mindbox.pushimages`, не экспортирован, с `grantUriPermissions`.
- `BigPictureStyle` получает `Icon.createWithContentUri(uri)`.
- Large icon — первый кадр, поэтому свёрнутая строка показывает его.
- Перед показом GIF-пуша удаляются файлы старше часа, которые не показывает ни одно активное уведомление.
  - Каждая загрузка пишет новый файл, поэтому повтор не перезаписывает картинку показанного пуша.
  - Час защищает загрузку, которая ещё не дошла до `notify`, и задержку, с которой новый пуш появляется в `activeNotifications`.
  - Отложенные (snooze) уведомления NMS тоже возвращает в `activeNotifications`, их файлы остаются.
- PNG и JPG, Android 13 и ниже и свой загрузчик идут старым путём, как раньше.
- Публичный API не меняется.

## Варианты для своих загрузчиков

1. GIF анимируется только при стандартном загрузчике. Свой `MindboxImageLoader` у клиента продолжает давать статику, как сейчас. Public API не меняется. Выбран.
2. То же плюс новый метод в публичном `MindboxImageLoader` для своих загрузчиков. Этот метод придётся поддерживать всегда. Можно добавить позже, ничего не сломав.
3. Свой layout с `ViewFlipper` из кадров. Он работает и на старых Android, но упирается в лимит битмапов в уведомлении, выглядит нестандартно и попадает под ограничения custom views с Android 12. Отброшен.

## Где хранить файлы

SystemUI перечитывает файл при каждом показе раскрытого пуша. Сейчас статичная картинка зашита в уведомление и пропасть не может.

1. `cacheDir`. Выбран. Система при нехватке места или пользователь через «Очистить кэш» может удалить файл. Тогда раскрытый GIF-пуш в шторке остаётся без картинки, пока его не смахнут. Свёрнутая строка сохраняет первый кадр.
2. `filesDir`. Картинка не пропадает. Но GIF попадают в Auto Backup приложения клиента, у которого лимит 25 МБ, и лежат там, пока их не удалит уборка.
3. Свой `ContentProvider` на `no_backup`. Нет ни очистки системой, ни бэкапа. Но это около 40 строк своего провайдера вместо стандартного `FileProvider`, и защита путей ложится на нас.

## Почему с Android 14

- Google обещает анимированные картинки в `BigPictureStyle` с Android 12 (страница возможностей Android 12).
- CleverTap и MoEngage показывают GIF в пушах с Android 14.
- На 12–13 мы не проверяли выдачу права на URI. Если права нет, пуш останется вообще без картинки, а это хуже статики.
- Порог можно опустить после проверки QA на 12–13.

## Ограничения

- Масштабирование center-inside (`mindbox_use_central_inside_notification_scale`) к GIF не применяется, кадры масштабирует система. GIF нужно готовить под пропорции big picture.
- Анимация начинается с кадра 0 при каждом открытии шторки. Если свернуть и развернуть карточку внутри открытой шторки, анимация продолжается с текущего кадра. Это поведение SystemUI, из SDK оно не управляется.
- Для URI-картинки `EXTRA_PICTURE` (bitmap) в уведомлении пустой. Потребитель, который читает только его, покажет пуш без большой картинки, но с первым кадром в large icon. Wear OS и OEM SystemUI закрыты, не проверялось.
- CleverTap и MoEngage пишут, что часть OEM, например Samsung, может не анимировать GIF даже на 14+.
- GIF целиком скачивается на диск до показа пуша, размер не ограничен. Большой GIF задерживает пуш на время загрузки (таймаут чтения 30 с).
- Файл неудачной загрузки остаётся до следующего GIF-пуша (через час и позже) или до очистки кэша.

## Что проверено

- Unit-тесты на Robolectric:
  - файлы получают уникальные имена;
  - провайдер отдаёт сохранённые байты по URI;
  - уборка удаляет только старые файлы, которых нет в активных уведомлениях;
  - GIF на 14+ даёт URI, на 13 и для PNG — только bitmap;
  - битый GIF не оставляет файла;
  - стиль уведомления получает URI-иконку.
- Эмулятор API 37 через `DebugPushReceiver` в PushOk:
  - анимация идёт;
  - свёрнутая строка показывает кадр 0;
  - после каждого открытия шторки анимация идёт с кадра 0, 5 раз из 5;
  - PNG-пуш выглядит как раньше;
  - ошибка загрузки уходит в `MindboxImageFailureHandler`.

## Что проверить QA

- Android 12 и 13: GIF-пуш показывает первый кадр, картинка не пропадает.
- Samsung и другие OEM на Android 14+.
